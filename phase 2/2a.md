# PHASE 2A — DRIVER HOME & NAVIGATION SHELL

## Objective

Build the mobile-first application shell and Driver Home experience.

This establishes the structure that later Driver features will plug into.

## Prerequisite

Phase 1 authentication must be working.

After login as Driver, the user enters the Driver application area.

Do not build advanced GPS, routing, AI, or incident functionality in this sub-phase.

---

# 1. DRIVER APPLICATION SHELL

Create a consistent Driver application layout.

Recommended main navigation:

* Home
* Trips
* Map
* Alerts
* Profile

Use an appropriate mobile navigation pattern.

Desktop/tablet layouts should adapt naturally.

---

# 2. DRIVER HOME

The home screen should prioritize the active operational task.

Recommended sections:

### Header

* Greeting
* Driver identity
* Current status

### Active Delivery

* Delivery/shipment identifier
* Origin
* Destination
* Current status
* ETA placeholder/data source
* Main action

### Current Trip

* Trip status
* Route summary
* Distance/ETA placeholder
* Current route condition

### Alerts

Show only important active alerts.

### Vehicle

Show a concise vehicle status.

### Quick Actions

Examples:

* View Trip
* Open Map
* Report Issue
* View Alerts

Do not overload the screen.

---

# 3. UI STATES

Implement:

* No active trip
* Active trip
* Loading
* Empty state
* Error state
* Alert present
* No alerts

The empty state should be designed intentionally.

Do not use generic lorem ipsum.

---

# 4. DATA ARCHITECTURE

Use structured data/state rather than duplicating values in UI components.

Prepare the Home screen to eventually consume:

* Driver data
* Active delivery
* Vehicle data
* Current location
* Route status
* Alerts

Use appropriate mock/development data only where backend data does not exist yet.

Keep mock data easy to replace.

---

# 5. RESPONSIVE DESIGN

Mobile-first.

Verify on:

* 430px
* 390px
* 375px

Also verify:

* 768px
* 1024px
* 1280px

No horizontal scrolling.

---

# 6. ACCESSIBILITY

* Semantic navigation
* Accessible labels
* Keyboard support
* Visible focus states
* Appropriate touch targets
* Good contrast

---

# 7. SCOPE RESTRICTIONS

Do NOT implement:

* Live GPS
* Route calculation
* AI
* Driver incident backend
* Advanced notifications
* Logistics company dashboard
* Authority dashboard

The UI may contain clearly defined entry points for future functionality where appropriate, but the actual functionality belongs to later sub-phases.

---

# 8. ACCEPTANCE CRITERIA

* Driver sees a polished Home screen after authentication.
* Navigation works.
* Active/no-active trip states work.
* Responsive behavior works.
* Existing authentication is not broken.
* No later-phase system has been accidentally implemented.
* No console errors.

# END PHASE 2A
