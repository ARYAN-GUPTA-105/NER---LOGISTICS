# PHASE 1B — ROLE-SPECIFIC LOGIN UI

## Objective

Build the login interface shown after a user selects a role.

## Prerequisite

Phase 1A must already be implemented.

## User Flow

Role selection
→ Selected role
→ Role-specific login
→ Login attempt
→ Success / error state

After success, STOP. Do not build dashboards.

## Login Form

Include:

* Role identity/header
* Email or username
* Password
* Show/hide password
* Remember me
* Forgot password
* Login button
* "← Change role"

## Role-Specific Identity

The login heading should adapt to the selected role:

* Driver Login
* Logistics Company Login
* Field Officer Login
* Authority / Admin Login

Use a shared login component wherever possible.

Do not create four duplicated forms unnecessarily.

## Validation

Email/username:

* Required

Password:

* Required

Use human-friendly messages.

Preferred:
"Incorrect email or password."

Avoid technical messages such as:
"ERR_AUTH_401"

Field errors must be clearly associated with their input.

## Required States

Implement:

* Empty
* Focus
* Valid
* Invalid
* Loading
* Disabled
* Incorrect credentials
* Network/authentication failure
* Successful authentication

Password visibility must work correctly.

Prevent duplicate submissions while loading.

## Change Role

Provide:

← Change role

This must return the user to role selection cleanly.

## Responsive Design

Desktop:

* Comfortable form width.
* Strong visual hierarchy.
* Professional composition.

Mobile:

* Mobile-first controls.
* Large touch targets.
* No horizontal scrolling.
* Comfortable spacing.
* Good keyboard behavior.

Test:

* 1440px
* 1280px
* 1024px
* 430px
* 390px
* 375px

## Accessibility

Implement:

* Semantic form
* Proper labels
* Keyboard navigation
* Visible focus states
* Accessible error messages
* Good contrast
* Accessible password toggle

## Visual Consistency

Maintain the design system created in Phase 1A.

The login experience should feel:

* Trustworthy
* Modern
* Technical
* Operational
* Professional

Do not introduce an unrelated visual style.

## Scope Restrictions

Do NOT build:

* Driver dashboard
* Logistics dashboard
* Field reporting
* Authority command center
* Maps
* GPS
* AI
* Route optimization
* Notifications
* Analytics

Successful login must stop at an authenticated success state.

## Acceptance Criteria

* Correct login appears for selected role.
* Change role works.
* Validation works.
* Password visibility works.
* Loading/error/success states work.
* Desktop is responsive.
* Mobile is responsive.
* No console errors exist.
* No later-phase functionality is introduced.

## Completion Report

Report:

* Files changed
* Components created
* Validation behavior
* Authentication-state behavior
* Testing completed
* Known limitations
* Whether Phase 1B is ready for Phase 1C
