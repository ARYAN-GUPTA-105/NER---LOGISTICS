# PHASE 1A — ROLE SELECTION UI

## Objective

Build only the first authentication screen where the user selects their platform role.

Do not build the login form in this sub-phase.

## Roles

### Driver

"Manage trips, routes and delivery status."

### Logistics Company

"Monitor your fleet and logistics operations."

### Field Officer

"Report incidents and road conditions from the field."

### Authority / Admin

"Monitor regional logistics and accessibility."

## User Flow

Open application
→ Authentication entry
→ Select one role
→ Continue

## Branding

Product name:

SMART NER LOGISTICS

Supporting text:

AI-Powered Logistics & Accessibility Platform

Do not invent official government logos or claims of official affiliation.

## Role Cards

Each role card must contain:

* Appropriate icon
* Role name
* Short description
* Selected state
* Hover state
* Keyboard focus state

Only one role can be selected.

The selected state must be visually obvious.

## Continue Button

Requirements:

* Disabled when no role is selected.
* Enabled when a role is selected.
* Clear hover/focus/active states.
* Keyboard accessible.

For this sub-phase, Continue should only move to the Phase 1B entry point or a temporary route/state.

Do not implement the login form yet.

## Responsive Design

Desktop:

* Strong visual hierarchy.
* Professional composition.
* Prefer a 2×2 role-card arrangement where appropriate.

Mobile:

* Stack or compactly arrange the cards.
* No horizontal scrolling.
* Comfortable touch targets.
* Readable text.
* Good spacing.

Test at:

* 1440px
* 1280px
* 1024px
* 430px
* 390px
* 375px

## Visual Direction

The design should communicate:

Logistics + Infrastructure + Intelligence + Reliability

Use subtle references to:

* Roads
* Maps
* Networks
* Location
* Movement

Avoid:

* Generic login templates
* Excessive gradients
* Excessive glassmorphism
* Excessive rounded cards
* Noisy backgrounds
* Excessive animation

## Accessibility

Implement:

* Semantic structure
* Keyboard navigation
* Visible focus states
* Accessible labels
* Adequate contrast
* No color-only meaning

## Role Data

Create one source of truth for the roles.

Recommended IDs:

* driver
* logistics_company
* field_officer
* authority_admin

Do not duplicate role metadata across components.

## Scope Restrictions

Do NOT build:

* Login form
* Real authentication
* Authentication service
* Dashboard
* Map
* GPS
* AI
* Reporting
* Fleet tracking

## Acceptance Criteria

Phase 1A is complete when:

* All four roles are clearly presented.
* Exactly one role can be selected.
* Selection state is obvious.
* Continue behaves correctly.
* Desktop layout works.
* Mobile layout works.
* No horizontal overflow exists.
* No console errors exist.
* Components are reusable and maintainable.

## Completion Report

Report:

* What was built
* Files changed
* Testing performed
* Known limitations
* Whether Phase 1A is ready for Phase 1B
